# VH-96 — Trim: the preview and handles

> **Status:** Band 4 · [blocked: VH-95]. Working detail only; the decision
> rationale goes to `decision-log.md` when the item ships.

## Intent

Maintainer request, 2026-09-30: "a preview of the video with handles to trim
start and end before export". This is the Trim step in VH-91's layout, over
the engine VH-95 provides.

## Done when

See the backlog line.

## Evidence / context

- A `<video>` on `URL.createObjectURL(file)` plays a local file with no
  request and without reading it into memory. The URL is revoked when the
  file changes.
- The browser's player and WebCodecs do not accept the same set of files. A
  source the pipeline can process may show no picture in `<video>`.
- The player's clock and the demuxer's both count container time, but
  nothing guarantees they agree to the frame — edit lists and a late first
  frame are where they would part. The pipeline measures both lanes from a
  shared origin (`source-timeline.ts`).
- The screen re-runs pre-flight whenever the selection changes, and takes
  Start down while it does (R-05). A changed range is a changed selection.

## Approach

- **Preview:** native `<video controls>`. The browser's own controls are
  keyboard operable and already known to the user; the trim controls sit
  beside them, they do not replace them.
- **Handles:** Carbon's range-slider pattern, built from two native
  `<input type="range">` on one track, each with its own visible label
  ("Start", "End") and an `aria-valuetext` in words. 44 px thumbs.
- **Without dragging** (WCAG 2.5.7): a time field for each end, and "Set
  start here" / "Set end here" buttons that take the player's current
  position. That is the precise route, and the one a switch or screen-reader
  user takes.
- **What is kept, in words:** "Keeping 12 minutes 4 seconds of 14 minutes 30
  seconds", updated politely. "Use the whole video" clears the trim.
- **Validation beside the field:** start before end, and no shorter than
  VH-95's floor. An invalid range takes Start down; it is never silently
  clamped.
- **On change:** the verdict, the time and the size are recomputed for the
  kept range. Committed changes only, and debounced — an arrow key held down
  must not queue a pre-flight per step. `beginSelection` already cancels the
  superseded one.
- **No preview:** if the player reports an error, the step says "A preview
  is not available for this file. You can still set the times." and the
  fields work alone.

## Constraints

- The trim controls are inside the job lock: `applyControlLock` disables
  them while a job or a save runs.
- The preview pauses when a job starts. Decoding it competes with the
  encode for the same hardware.
- Nothing autoplays. `prefers-reduced-motion` has nothing to suppress,
  because nothing moves until the user presses play.
- The object URL must not read as egress. Criterion 9's watch counts
  requests that leave the origin or carry a body; confirm a `blob:` URL is
  neither, in the harness.
- Responsive: on a phone the player is full width and the fields stack.

## Open questions

- What one arrow-key press moves a handle by. Default: one second, held in
  `src/config/`, with the time field for anything finer.
- Whether the fallback shows a still frame at each end, decoded by the
  worker. Default: no — fields alone — until a real file needs it.
- Whether the two clocks agree on the corpus. Settled by the Done-when's
  frame comparison; if they do not, the handles read the demuxer's clock and
  the player is shown offset.
