# VH-53 — Repository review remediation

> **Status:** Band 1, in progress on `codex/repository-review-implementation`.

## Intent and boundary

Implement the highest-severity verified, non-protected findings from the
updated 2026-08-26 review that can be proved deterministically. Work in an isolated `/private/tmp`
worktree because the checkout is OneDrive-synced, while keeping the tracked
`pm_skills/project/` record on the branch. Do not edit protected specifications,
meter code or the EBU acceptance harness without explicit maintainer approval.

## Implemented on this branch

- OPFS directories are claimed before creation, held through result lifetime,
  swept only while unlocked, and disposed with retryable, single-owner cleanup.
- Immutable selection and result authorities reject stale readiness, overlap,
  implicit replacement and false download completion; source/destination entry
  identity is checked before write access where the browser can prove it.
- Cancellation is registered before asynchronous work, propagated across both
  lanes, and paired with bounded output/workspace cleanup and retained-error UI.
- Inspection, probe and encode share Mediabunny's selected primary tracks and a
  single source timeline; delayed lanes and gaps are preserved with bounded
  zero-fill rather than deleting source PCM.
- Audio planning performs a bounded complete-chain gain solve. Finished output
  picture and sound are decoded and classified fail-closed against the strict
  loudness/true-peak pair; failed or unavailable evidence stays visible.
- Acceptance, public-asset inventory, cross-engine orchestration, lifecycle,
  diagnostics and deployment checks now distinguish pass, fail and manual work
  instead of treating missing evidence as success.

Deterministic runtime and release mechanisms have focused regression coverage;
workflow permissions and browser-only behaviours remain code/manual review.
A real Chromium acceptance run
reported five automated criteria passed, none failed and six correctly left
for a person: all four loudness outputs were within 0.02 LU and no higher than
-2.10 dBTP; all 12 sync markers were found with 9.8 ms offset and 9.0 ms drift;
and worker cancellation left zero OPFS job directories. Baseline `66227e5`
passed 355 tests with one skip. The final canonical gate passed all 56 test
files: 529 tests passed and one was intentionally skipped; type checking, lint,
the isolated production build, Markdown, links and project-memory structure
were also green. Five existing soft memory-budget warnings remain reported.

The branch was manually deployed to the existing pilot on 2026-08-26 after the
GitHub Pages environment was restricted to the exact `main` and experimental
branch names. Deployment evidence requires the workflow head SHA and live build
identity to match; that check passed. `main` remains the unchanged manual
rollback ref.

A read-only re-audit found the existing samples sufficient for VH-50: 23 real
sources cover a useful loudness, duration, geometry and audio range. They do
not cover mobile/HDR risks. `CULT2011.mp4` is quarantined as a hostile AAC
compatibility case pending browser-decoder evidence and must not be treated as

- **Real media/engines:** rerun VH-50 loudness on representative recordings;
  explain the `CULT2011.mp4` browser-decoder result; exercise source overwrite

  and sync-writer OPFS, multi-tab lock/sweep, cancel/error cleanup, wake/unload

  metadata round-trip in supported browsers.
- **Format risk:** confirm first-picture behaviour and AAC sync in independent
  real players, and 4K60 H.264 conformance on actual encoders; the measured
  round-trip delay and capability refusal are honest but not player/codec proof.
- **Release evidence:** complete assistive-technology and zero-media-egress
  rehearsal. Branding/legal provenance remains a maintainer decision; hashes
  prove asset identity, not permission to publish.
- **Independent evidence:** compare finished true peak with an external
  conformant meter rather than treating the app's own detector as independent.

No pilot blocker closes from unit tests alone. No runtime dependency was added,
