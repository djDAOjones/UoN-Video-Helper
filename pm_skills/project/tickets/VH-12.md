## The one implementation fact that is easy to get wrong

**The alpha is PREMULTIPLIED, matted with black.** Measured on the white
variant, whose artwork reaches RGB 255 when opaque: RGB is exactly capped at
alpha at every point of the ramp (t=0.16 → 16/16, t=0.40 → 75/75, t=2.00 →
255/255).

So the composite is:

    out = brand_rgb + source_rgb × (1 − alpha)

**not** the usual straight-alpha form `brand × a + source × (1 − a)`. Using the
straight form double-darkens the logo and fringes every edge — wrong in a way
that looks plausible. Premultiplied is also the right choice for us because it
resamples cleanly, and branding must scale from 4K down to 640×480.

## Alpha decode is verified — on Chromium only

Mediabunny merges colour and alpha on the CPU (`ColorAlphaMerger`), so it needs
only ordinary VP9 decode, not native browser alpha-video support. All four
onsets and one tail pass through `/spike-alpha.html`, which reads back pixel
alpha; the readings cross-check against the masters (Fade uniform, Slide
hard-edged).

**Safari 26 and Firefox are unverified** — the in-app browser is Chromium. The
spike page exists so that check is one URL. If Safari ever fails VP9 alpha,
retry VP8 with a corrected encode before concluding; the VP8 attempt here
failed its own round-trip and was not pursued because VP9 works and is smaller.

## Done, 2026-08-25 — the real closing asset is in the pipeline

`src/config/branding.ts` was rewritten to the two-part model: style, colour and
mode types; the measured 1 s / 4 s split; `closingAddedSeconds(mode)`;
`modeNeedsOnset(mode)`; and `brandingAssetHeight` replacing the old frame-rate
variant matching, which had nothing left to match. Opening keeps the older
single-clip placeholder model, clearly separated and marked VH-23.

`loadBrandingClip('closing', …)` now fetches the real tail. Verified in a
browser via the acceptance harness, which logs
`clip loaded {segment: closing, url: /branding/closing-tail-blue-1080p.mp4,
durationSeconds: 4}` and still finishes 5 pass / 0 fail / 4 need-a-person.

Effectively this makes **clean cut** work end to end on real assets, since that
mode is the tail alone.

Since then: `src/media/composite.ts` implements the premultiplied composite
with tests that pin the WRONG formula as well as the right one, and
`loadClosingOnset` loads the transparent onsets — both container formats are
now offered on every fetch, so WebM works. Verified through the app's own
loader in a browser, not just against Mediabunny directly:
`loadClosingOnset -> 1.000s`, `loadBrandingClip -> 4.000s`.
