# VH-48 — Stream-copy fast path for "best quality"

Promoted out of the icebox 2026-08-25, where it sat as D10. One of the two
reasons it was rejected has fallen. The other has not.

## What it is

Leave the source video stream untouched, encode only the branding, and
concatenate. The content region becomes generationally lossless rather than
merely good, and the job near-instant rather than the 6.3x real time VH-M2
measured.

## Reason one has fallen

Rationale §4.3 rejected it partly because it "degrades badly on VFR sources —
which, per 4.2, are common here". VH-24 measured the corpus and they are not.
All eight frame-rate anomalies trace to PowerPoint writing a nominal 30 fps as
1000/33, and Teams is 16.000 CFR flat. D10's own revisit trigger reads "when v1
is stable and there is real data on how many sources are CFR". There is now.

## Reason two has not

§4.3's other objection stands, and it is the harder one: byte-exact codec
parameter matching — profile, level, SPS/PPS, pixel format, timebase — between
the copied source and the encoded branding, with silent A/V drift discovered
after publication as the failure mode. This item does not wave that away. It is
why it carries [sign-off] rather than being picked.

## The case is narrower and safer than it first looks

Video and audio are separate tracks, so re-levelling the audio — which every
job does — does not force a video re-encode. And since VH-45 withdrew the
transition controls, **every job on the deployed site takes the hard cut**,
which composites nothing. Today's default job is therefore untouched content
picture plus a four-second closing: exactly the shape this path wants.

That stops being true when VH-25 lands picture fades and VH-44 restores the
overlay modes. So the deliverable is not a switch but a predicate.

## Done when

Scoped and signed off, then: a `canStreamCopy(source, choice)` predicate exists
and is honest — already CFR, hard cut, no picture fade, codec parameters
matched — the fast path is taken only when it returns true, anything else falls
back to the encode path rather than producing drift, the output plays in a real
decoder, and the content region is bit-identical to the source's.

## Not a free win

If the predicate is too loose the failure is silent and found after
publication. If it is too tight the path never fires and the work was wasted.
Scoping should decide which of those two errors is cheaper here before any of
it is built.
