# VH-95 — Trim: the engine

> **Status:** Band 4 · unblocked 2026-09-30 (VH-30 signed off). Working detail only; the decision
> rationale goes to `decision-log.md` when the item ships.

## Intent

A kept range, in source time, that every reader of the source honours. No UI:
the range arrives in the worker requests and is proved in the acceptance
harness. VH-96 puts a face on it.

## Done when

See the backlog line.

## Evidence / context

Read against HEAD on 2026-09-30. Everything that walks the source today walks
all of it:

| Where | What it does now | What the range changes |
| --- | --- | --- |
| `workers/protocol.ts` | `preflight` and `process` carry a file and a preset | both gain an optional range |
| `media/audio-plan.ts` `traverse` | `sink.samples()` over the whole track, in passes A, B and B′ | the same range in every pass |
| `media/pipeline.ts` audio lane | `sink.samples()` again, for pass C | the same range again |
| `media/pipeline.ts` video lane | `sink.samples()`, rebased to the shared origin | ranged; the in-point becomes the origin for both lanes |
| `media/pipeline.ts` spans | `videoSpanSeconds`, `audioSpanSeconds` from whole-track durations | the kept spans, which feed `closingTimeline` |
| `media/pipeline.ts` freeze | `findFreezeFrame` searches back from the last frame fed | unchanged in form — the last frame fed is now the out-point |
| `media/probe.ts` | `samples(0, CALIBRATION_PROBE_SECONDS)`, extrapolated over the whole duration | starts at the in-point; extrapolates over the kept duration |
| `workers/job.worker.ts` `handlePreflight` | `analyseSourceAudio` over the whole track; size from `durationSeconds + LONGEST_CLOSING_SECONDS` | warnings and size describe the kept range |

`samples(start, end)` is inclusive of the start and exclusive of the end, on
both sinks (Mediabunny 1.55.2, read from its type definitions).

## Approach

- One range type, in seconds of source time, validated once and passed down
  as data. Absent means the whole file, by the code path that runs today.
- **The same range in every audio pass.** `audio-plan.ts` already says why:
  if one pass is indexed differently, the envelope built from the short-term
  curve is applied to a stream it was not measured on (VH-74).
- **Sample-accurate edges.** Audio arrives in decoded blocks of roughly
  20 ms. The first and last are sliced, or the two lanes part company by up
  to a block at the in-point.
- **A fade at each cut.** Today content fades in only after an opening and
  out only before a closing. A cut mid-sound clicks; both edges take
  `BOUNDARY_FADE_MS`, whatever adjoins them.
- **A floor on the kept length,** in `src/config/`. The meter gates on 400 ms
  blocks and needs 3 s for a short-term reading, and the build needs 1 s of
  picture.
- The source warnings are measured on the kept range, so trimming a long
  silence removes the warning about it.

## Constraints

- Loudness is still measured on source content only — now the kept part of
  it. Spec §4.4 stands.
- `src/audio/` is untouched: the range is applied where samples are read,
  not inside the meter. The EBU Tech 3341 harness must not need re-running,
  and if a change makes it need to, the change is in the wrong place.
- After VH-83, never beside it. Both rework `planAudio`.
- VH-19's spread sampling windows, when adopted, fall inside the kept range.
- The harness, not a mock: a trimmed case under criteria 2, 6 and 8 in
  `src/acceptance/run.ts`.

## Open questions

- Whether a late-starting audio track (VH-74) and an in-point between the
  two lanes' starts need their own harness case. Default: yes — it is the
  case the shared origin exists for.
- Naming. `onset-trimmed` is already a warning code, about encoder delay
  (VH-55). The range needs a word that cannot be mistaken for it.
