# VH-128 — The title card: Submission

## Intent

The Submission layout of the title card, for a student handing a video in as coursework: everything a marker needs, on one card before the video. The fields are the owner's, set on 2026-10-18; student ID numbers rather than names, for anonymous marking.

## Acceptance criteria

- Submission shows, each labelled: module title and code; assignment title or number; module convenor or tutor; one or more student ID numbers; the running time; the date the card was made.
- The first four are typed and required; until each is filled, the page says which is missing and what to do, and Create waits.
- The running time is computed, never typed: the kept range after trimming, without the title card or the closing (the owner: "not including anything added by the app, but discounting trimmed material"); it follows the trim handles.
- The date is the device's date when the card is made, labelled so it cannot be read as the submission date (the owner: "clarify: not submission date").
- A student ID number is checked against a format set in `src/config/`; no field asks for a name.
- The ID numbers and the convenor's name never reach the logger, the diagnostics bundle, the suggested file name or the file's metadata.
- The card reads as a student's submission and carries no University logo, so it cannot pass for a University publication.
- The page's new words are in all three language tables, by VH-105's sheet route.
- Spec §4 and §9.1 say so, in text the owner approves (docs/ is protected).
- `npm run check` green; checked in Chrome on a sample, trimmed and not.
