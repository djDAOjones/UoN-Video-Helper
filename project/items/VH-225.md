# VH-225 — The rename to UoN Video Finisher

## Intent

The owner renamed the app on 2026-10-28: "it is to be called UoN Video Finisher (rather than UoN Video Helper)", and "the next release must contain the rename" (Notes). This item changes the name the app shows, in every language, and on his later answer the repository and the Pages address with it, while the hidden identifiers that hold saved choices and stored jobs keep their names, since renaming them without a proved migration loses data. It is built after VH-210 and before VH-220, on his word, so the checks VH-220 to VH-224 and VH-203's after-run read the renamed page, and before VH-204, so the release contains it.

## Acceptance criteria

These six are drafts from the raise, which VH-225's own worker refines before its build, with Codex astra's blind check, recording any change.

- **The visible name** is "UoN Video Finisher" everywhere the app shows its name:
  - `index.html`: the title, the h1, and the statement's "covers" line;
  - en-GB `app.title` and `statement.covers`;
  - new ms-MY and zh-Hans names, because "Pembantu Video UoN" and "UoN 视频助手" both translate "Helper"; they join the open native check before the release;
  - the feedback email subjects in `src/config/feedback.ts`;
  - the Xerte package's text and its zip name in `scripts/package-xerte.mjs`;
  - the translator note in `src/i18n/sheet.ts` (about `:475`) and the boot log in `src/main.ts` (about `:223`);
  - README, `project/profile.md`, `acceptance.html`, DEV-INFRASTRUCTURE.md;
  - the tests that assert any of these, updated, not deleted or skipped.
- **`docs/`:** the spec's title (`docs/01-specification.md`, `:1`) and `docs/04-init-prompt.md`, the name swap only, and no other `docs/` edit. The owner's word covers the name. Any other `docs/` change is a stop.
- **Hidden identifiers are kept:** the localStorage keys `uon-video-helper:*`, the OPFS folder `uon-video-helper-jobs`, the job name `uon-video-helper-job` and the package name. Renaming them without a migration resets saved choices and orphans stored jobs, which is data loss (house-conventions, "Fail loudly on data loss"). A migration is in scope only if it is designed, tested and proved with no loss, and Codex agrees.
- **The repository and the Pages address are renamed,** on the owner's answer (Notes): the repository github.com/djDAOjones/UoN-Video-Helper and the Pages address djdaojones.github.io/UoN-Video-Helper/; vite's base, the branding path, `project/profile.md`'s remote URL and every link to the old address follow. Renaming the repository is a GitHub setting: his click, or a session's with his go-ahead at that step, planned into this item, never done unasked. The project folder on his Mac is not this item's: it is [VH-226](VH-226.md)'s, after the release.
- **The walker:** if it asserts the app's name, the change to those assertions is named here and proved on both layouts. Any other walker change is a stop.
- **Stage rule:** VH-203's stage rule. The before and after cover the name's surfaces in every language and layout.
