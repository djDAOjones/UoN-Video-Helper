# VH-150 — The job's state after VH-141: the stop withdrawn, a fresh bar, one primary button, Show progress withdrawn, and pins

## Intent

VH-141 fixed nine state defects, and the review of Codex's 21 October run found that it left or made several more. A user who reaches any of them sees it:

- after a watchdog failure, "The job is stopping" stays as the page's last word;
- a job can show the last job's progress bar;
- an unreadable file chosen beside an unsaved result makes the chooser a second primary button;
- "Set end here" hands focus to the start field;
- a kept result's warnings nest one notification inside another.

VH-141 also added a Show progress checkbox its criterion did not ask for, and the owner has now withdrawn it. Most of VH-141's criteria rest on browser evidence alone, with no source pin. This item fixes the defects, withdraws the checkbox and pins the rest. It goes first in Phase 5 because a user can see what it fixes.

## Acceptance criteria

R2-n is finding n under Rank 2 in the review. Rank-3 findings are named by their words there.

- **R2-1.** Once the worker has settled after a watchdog failure and Create has returned, the status no longer holds "The job is stopping. Please wait before trying again." (`create.stoppingAfterFailure`). A change of language does not speak it again.
- **R2-2.** Starting a job resets the bar's value and the progress text, so no job shows another job's percentage or words.
- **R2-3, the owner's word of 2026-10-22.** While an unsaved result stands, choosing an unreadable file leaves the chooser secondary, and the result's Save stays the only primary button. The chooser becomes primary again only when no result stands.
- **R2-4, the owner's word of 2026-10-22.** Show progress is withdrawn:
  - its checkbox and help text leave `index.html`;
  - `create.showProgress` and `create.showProgressHelp` leave the three tables and the sheet;
  - its handling leaves `src/main.ts`.

  Announce progress and its remembered choice stay. Once Cancel is pressed or a failure is shown, the bar, stage, time left and tab title still stop moving (VH-141's V-14). Show progress's tests become pins that it is gone, so no test is deleted without a replacement.
- **R2-4, the record.**
  - VH-141.1 is retired, and its replacement drafts, for the owner's approval, the spec §9.3 reading of WCAG 2.2.2 that the page then relies on: the moving bar, stage, time left and tab title report a job the user started and is waiting for, so they are essential to it. Announce progress controls the spoken milestones, and outcomes are always announced.
  - VH-141.2 is retired, and its replacement drops "try Show progress".
- **R2-5.** Source pins hold:
  - `lifetimeOf` starting from `delivered`;
  - warnings surviving a redraw;
  - `saveError` cleared by `setSaveStatus`;
  - the `onStage` guard;
  - the emphasis `clearTrim('unreadable')` gives, as R2-3 rules it;
  - `.textarea:disabled`.
- **Rank 3, "Two notifications, one inside the other".** No notification is nested inside another. A kept result's warnings sit beside the result's notification, not in it. "None of these stop you continuing" (`warnings.reassurance`) does not show under a finished video.
- **Rank 3, "Dead restore code".** The dead restore in `runPreflight` is removed. When a storage re-check still fails, the block shows without "Video read." being said again first.
- **Rank 3, small items.**
  - The redundant `!cancelRequested` check is removed.
  - "Set end here" hands focus to the end time field.
- **The gate.**
  - Tests by category.
  - Strings through the sheet.
  - No new token.
  - `npm run check` green, with no test deleted or skipped.
- **Checked in Chrome** at 1280 and 375 px in the three languages:
  - a watchdog failure;
  - a second job;
  - an unreadable file chosen beside an unsaved result;
  - a kept result with warnings;
  - a storage re-check that fails;
  - both Set buttons.
