# VH-168 — The file chooser's words in a translated page: kept native and recorded, or drawn by the page on the owner's exception

## Intent

In a Chinese or Malay page, the first and only filled button says "Choose file" and "No file chosen" in the browser's language, between a translated heading and a translated hint (V-35). Chrome draws those words inside the native file input, and CSS cannot change them. Anyone whose browser's language differs from the page's sees it. The page's rule is no new element, so the design pass recommends keeping the native chooser and recording the limitation, unless the owner makes an explicit exception for a label styled as the button that says "Choose file" in the page's language. This item carries that ruling and whichever way it goes.

## Acceptance criteria

- The owner's ruling first: native (recommended under the rule) or a `label`, an element the rule forbids without an explicit exception.
- If native: a decision records the browser-language limitation; any statement wording goes to VH-137; the item closes.
- If the label: the native `input type=file` stays the control, focusable, still the drop zone's input; its accessible name matches the visible "Choose file" and the step's heading; the label takes the input's focus, disabled, primary and forced-colour states; the chosen file's name shows from selection, before and after reading, wrapping as VH-165 sets, with the live read line's announcement checked in three languages; drop path, keyboard path (Tab, Space, Enter) and a screen reader's reading checked.
- Three languages at 1280, 375 and 320 px; light, dark and forced colours; 2.4.13 and 2.5.5 re-checked for the new face; the before is the two `v35-` captures.
- `npm run check` green with no test deleted or skipped; spec §5's or §9's words, if they name the browser's button, drafted as a wish line for the owner.
