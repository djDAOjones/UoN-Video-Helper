# VH-168 — The file chooser's words in a translated page: kept native, the limitation recorded

## Intent

In a Chinese or Malay page, the first and only filled button says "Choose file" and "No file chosen" in the browser's language, between a translated heading and a translated hint (V-35). Chrome draws those words inside the native file input, and CSS cannot change them. Anyone whose browser's language differs from the page's sees it. The page's rule is no new element, so the design pass recommends keeping the native chooser and recording the limitation, unless the owner makes an explicit exception for a label styled as the button that says "Choose file" in the page's language. The owner ruled native: this item records the limitation and changes no page.

## Acceptance criteria

- The owner's ruling: native ("Keep the browser's own file chooser and record the limitation."); the label is withdrawn and no element is added.
- A decision records the browser-language limitation: the chooser's button and its "No file chosen" follow the browser's language, its accessible name the page's.
- The spec and the accessibility statement read: if either claims the chooser's words are translated, the spec's correction is a wish line for the owner and the statement's goes to VH-137; if neither does, the decision says so.
- No page change; `npm run check` green with no test deleted or skipped.
