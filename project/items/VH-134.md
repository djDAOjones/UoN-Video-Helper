# VH-134 — The spec caught up: six edits drafted for approval

## Intent

The specification is authoritative, but in six places it no longer says what the shipped app does: the three page languages (§9), the trim preview (§9.1 step 2), the five named stages (§9.2), and three points in §9.3 (format identifiers, paragraph spacing, and the 3.1.4 exceptions). A reader, or an agent, trusting the spec is misled in each. The agent drafts all six in one diff for the owner, and applies only what the owner approves, word for word.

## Acceptance criteria

- Each of the six sign-off debts in Notes has a drafted edit at its section, shown to the owner together as one diff before anything is written to the spec.
- Each approved edit is applied word for word; one not approved stays a wish line, never dropped.
- §9.3's 3.1.4 list matches the exceptions `test/readability.test.ts` records, each with its four fields.
- `docs/01-specification.md` stays within the 7,800 words rules.md's By task table allows it.
- `npm run check` green with no new skip; `node tools/check.mjs` raises no budget warning for the spec.
