# VH-167 — One reading measure: a rem width for every size and language, so running text stops at one place

## Intent

Running text stops at four widths in one column: 489 px for body text and 428 px for helper text in English and Malay, 640 and 560 px in Chinese, because `--measure: 55ch` and `--measure-cjk: 40em` resolve against each element's own font (V-33). Two prose spans take no measure, so a Chinese fact note can run about 46 glyphs, and the toggletip's paragraphs sit 8 px apart. This item makes the measure one physical width in `rem` for every size and language, so helper and notification text stop where body text does and the column no longer jumps when the language changes.

## Acceptance criteria

- V-33: `--measure` a `rem` width, starting at 28rem and confirmed by line count in the browser, any change from 28rem recorded at close; `--measure-cjk` and its `:lang(zh)` rule retired; the measure on `.fact-note`, `.radio-detail` and the text fields; `--paragraph-gap` between the toggletip's paragraphs; every cap yields to its container.
- 1.4.8 counted per rendered line by `wcag-checks.mjs` after the fix: no line over 80 characters in English or Malay at 14 or 16 px, none over 40 CJK glyphs in Chinese, counting full-width equivalents; the measure table in the inventory shows one width per language for every running-text kind.
- The before captures taken again side by side; three languages at 1280, 375 and 320 px; light, dark and forced colours; 1.4.10 and 1.4.12 re-checked.
- `test/stylesheet.test.ts`'s `55ch` pin changes to the approved value, with the behavioural width check kept or strengthened; `UI-STANDARDS.md`'s 1.4.8 line says the new measure; `npm run check` green with no test deleted or skipped; no control or element added.
