# VH-215 — The submission card gives the length the new video has, not the length the file's index declares

## Intent

The submission card's running time is the part kept, computed on the page from the trim and the index before the job starts (`keptDurationSeconds`, `src/main.ts`, `:2956–2961`; `src/ui/title-card-step.ts`, `:306–319`), so a cut-short file with no closing draws "30 seconds" on a 21-second video (wish VH-139.5). The spec asks for "the part kept after trimming, without the card or the closing" (`docs/01-specification.md`, `:128`), which for a cut-short file is what is made. The length made depends on both tracks (`src/media/ends-early.ts`, `:158–166`): pre-flight's analysis pass decodes the whole kept sound before the encode (`:11–16`), but the picture's end is found only during the encode (`src/media/pipeline.ts`, `:840–842`), after the card is drawn. This item puts the length made on the card, by a route it finds first and bounds.

## Acceptance criteria

The build says which route and why, timed on the largest fixture. If the route does not fit this item, the trace and its timings close it, and the build becomes its own fix item before VH-203.
