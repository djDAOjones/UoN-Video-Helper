# VH-161 — Offline after first load: the cache strategy spec §11 asks for

## Intent

Spec §11 says the app must work after first load with no network, except for the branding assets, which are cached. Nothing in `src/` caches today. VH-14's 2026-10-01 triage found that the closing clips are fetched per job with no cache, so they are most of what offline use has to hold, and the worker needs no splitting for it. PLAN-6 split this off from VH-14 so that deployment can close at the release, and it waits until after the release.

## Acceptance criteria

- After one full load, with the network off, the page loads, a job runs with a closing, and nothing fails for want of a fetch. This is checked in Chrome both on Pages and on the Xerte package.
- The mechanism works under a relative base on a flat Xerte upload, and needs no special response headers (spec §11, deployment).
- The cache holds only the app and its branding assets, never media (rules, no media egress).
- A new build replaces the old cache, so a user is not held on a stale version.
- `npm run check` green with no new skip.
