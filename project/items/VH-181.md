# VH-181 — One name for step 4: “Closing graphics” in three languages, spec §6 to match

## Intent

Step 4 has two names. Its heading and legend say "Closing branding", and its own lines say "closing graphics" (V-45, rank 2). Both were the owner's words of 21 October (VH-148). On 23 October the owner ruled for one name: "use “Closing graphics” everywhere, with the specification’s §6 line changed to match. It’s what the step’s own lines already say, and having two names breaks the project’s “no synonyms” rule." This item renames the step in three languages and makes the one spec edit the owner approved. It changes strings only, adds no element, and comes after VH-180 so that both string items are measured on VH-179's final CSS. Codex astra's integrated check in VH-176 reads it with the rest.

## Acceptance criteria

- **V-45, the step's name.** Step 4's heading (`steps.closing`) and its fieldset legend (`closing.legend`) say "Closing graphics" in English. In Chinese and Malay they take the noun those tables already use for "closing graphics" in step 4's lines, so each language has one name, not two. The Chinese and Malay rows are the agent's drafts, marked so for a native reader. `index.html`'s fallback text, `src/i18n/sheet.ts`'s row label and `test/screen-text.test.ts` follow. `README.md`'s product line takes the same name.
- **No synonym left.** A search of `src/`, `index.html` and `README.md` finds no "Closing branding", "结尾品牌标识" or "Penjenamaan penutup". Every other name the page uses for the closing on its own, such as "closing card", is read and listed in the close with what it names. A third name for the same thing is changed to the one name. A different thing, such as a card image file, keeps its own word, and the close says why.
- **Spec §6, approved by the owner.** `docs/01-specification.md` line 626 reads "4. **Closing graphics** — animation type, onset and colour (§4.3)." The spec's word count is checked against its 8,100 budget: it stands at 8,074 and two words replace two.
- **V-18 not worsened.** The painted file button's bounds in J1's first screen at 1280 × 900 and 320 × 568, in three languages, are read beside VH-180's after-reading. In none of the six cases does the button sit lower, and in English at 1280 it stays wholly inside the first screen. If any case is worse, the item stops and the owner is asked.
- **Measured, before and after, with the pass's walker:** S-15 and S-47 (step 4), and every record that draws the renamed string, with the measure, overflow, type and text-contrast instruments. All of it in three languages and in light, dark, forced-light and forced-dark. The table is kept in the bundle's measurements folder as vh181-name-2026-10-23.md. The language parity test (`src/i18n/tables.test.ts`) is green.
- **VH-176's stage rule, kept:** WCAG re-checked for what it touched (2.4.6, 3.2.4, 1.4.8, 1.4.10). No control, checkbox or element is added. `npm run check` is green with no test deleted or skipped, and the digest rule applied is named (rule 8). Codex astra checks the final candidate diff before commit, and the commit carries `Checked: gpt-6-astra — <verdict as given> — V-45`.
- The report's Disposition row for V-45 names this item and its evidence file.
