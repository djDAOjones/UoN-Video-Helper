# VH-151 — Disabled controls look disabled, and the trim field never forces a sideways scroll

## Intent

The review of Codex's 21 October run found four places where the page looks other than it is:

- VH-148's inset select arrow takes the wrapper's colour, so a locked select's arrow still looks live, in forced colours too.
- The browser-drawn "Choose file" button keeps a solid edge while a job runs.
- An invalid textarea's rule outranks the dashed disabled edge.
- VH-144's trim-field floor never shrinks below 12 rem, so the page would scroll sideways in a frame narrower than about 290 px (a Xerte frame), or at 320 px with an 18 px default font.

VH-145's grouping also left a comment over the wrong rules, a heading weight on a status glyph, a dropped WCAG comment and weight values no test pins. All of these are in `src/styles/app.css` and its test, so one change fixes them. The item comes second in Phase 5 because a user can see them.

## Acceptance criteria

R2-n is finding n under Rank 2 in the review. Rank-3 findings are named by their words there.

- **R2-6.** A disabled select's arrow takes the disabled text colour, from `.select-wrap:has(.select:disabled)::after`, and GrayText in the forced-colours block. Checked under None at 375 px in light, dark and forced colours, against the review's `locked-onset-375-*.png` captures.
- **Rank 3, "The disabled Choose file button".** `.file-input:disabled::file-selector-button` takes the dashed disabled edge that every other disabled button has (VH-148's clause 11).
- **Rank 3, small items.** A disabled textarea keeps its dashed edge when `aria-invalid` is set.
- **R2-11.** The trim field's flex basis and `min-width` are `min(var(--field-min-width), 100%)`, which the stylesheet test already exempts. The page does not scroll sideways in a 280 px frame, or at 320 px with an 18 px default font, in English, Chinese and Malay, under either switch.
- **Rank 3, VH-145's weight tokens.** The "Productive group heading…" comment sits over only the rule it describes. `.check .mark` keeps its rendered weight through a token named for its role, with no visible change.
- **Rank 3, VH-145's link rules.** The WCAG 2.5.5 comment explaining why `.notification-link` is 44 px is put back.
- **Rank 3, VH-145's pins.** `test/stylesheet.test.ts` pins the 400, 600 and 700 weight values and the body rule's weight, and it refuses a literal weight inside a `font:` shorthand.
- **The gate.**
  - No colour changes except the arrow's.
  - No new token except a role name the weight criterion needs.
  - Tests by category.
  - `npm run check` green, with no test deleted or skipped.
  - Checked in Chrome with the walker at 1280, 375 and 320 px in light, dark and forced colours, with no target under 44 px.
