# The third design pass — the plan, 25 October 2026

The owner asked that Phase 8 end with an analysis of design, UX and
accessibility "equivalent to that which started that work", adding: "it
must be as thorough as before" (PLAN-8, 2026-10-25). The work that
started Phase 8 is Phase 7's second pass, so this pass repeats it stage
for stage on the Phase 8 build: VH-197 to VH-203 are VH-170 to VH-176,
one for one, and VH-195 is the close, as VH-177 was. Phase 7's plan
([`plan-2026-10-22.md`](../../2026-10-22/design-pass-2/plan-2026-10-22.md))
is the base; this one is at least as broad in every dimension, and says
where it goes further. Codex astra critiques this draft before the
owner's approval, and what changes is recorded here. Each stage's item
file carries its acceptance criteria; this document carries the method
they share.

## The rule that holds throughout

The app stays simple: consolidate; no new control, checkbox or element;
the progress bar stays. Phase 8 added two elements on the owner's own
word, the finished card's player (VH-192, Q3) and the MP4 "?" (VH-196);
they are judged like everything else, and the rule still binds every
remedy. The rule constrains remedies, never the report: an unmet
criterion is reported truthfully, and a remedy that would need a new
element goes to the owner flagged and recommended against.

## The instruments

`reviews/2026-10-22/design-pass-2/evidence/measurements/walker/` into
this bundle's `evidence/measurements/walker/`, its source revision
named; the old bundle stays untouched. Before the matrix runs, VH-198
qualifies it with Phase 7's rules, unchanged:

- **No silent passes.** The expected records are declared; each run
  asserts the language, mode and state it reached; a fresh run
  directory; missing, duplicate, stale, failed or wrong-view records
  fail the run. Every instrument has "cannot determine". A resumed part
  supersedes failed records and never counts them.
- **Proved to detect.** Temporary failing fixtures in the scratchpad,
  never in `src/`: VH-171's three (an overflow, a focus ring too small,
  a control with no accessible name), VH-172's two (`pressed`, `type`),
  and one more for the player: a finished card whose `<video>` has
  lost its name and left the tab order, which the accessibility-tree
  and keyboard instruments must each catch.
- **The manifest.** Source commit, instrument revision (hashed, one
  revision across every part, as VH-176 achieved), browser and OS,
  viewport, scaling method, fixture identity, expected and observed
  coverage, `observedKeysSha256`, and what stayed unresolved.
- **The accessibility tree** from Chrome's Accessibility domain beside
  the DOM; a live-region change logged as a DOM change and an exposure,
  never as what a screen reader says.
- **Keyboard verification apart from setup.** Keys only, forward and
  back, through the native selects, both players' controls, both "?",
  the dialog's entry and exit, and focus after cancel, refusal,
  completion, a save and retry. A native interaction it cannot drive
  stays unverified.
- **Rendered focus and targets** by pixels, as VH-179 left them: the
  file button, both trim thumbs, the band, both forced palettes, and
  now the player's controls and the second "?". Targets from the
  clickable area, each exception argued.

## Stages

Each stage is one item, about one session; a chat manages one or two
items before its 200k line. Every stage close keeps the contract: the
gate and the checker green, the digest rules named, the item's files
only, `git fetch` before the commit, the push and its Pages deploy
checked. Evidence is kept small: the plan, the briefs and Codex's
outputs, the walker, the manifest, one digest per instrument, and only
the captures a finding or verification cites; the full run stays in the
scratchpad.

| Item | Stage | Ends with |
| --- | --- | --- |
| VH-197 | The plan, with Codex's critique | The owner's approval; this commit |
| VH-198 | The instruments re-proved; Codex's blind review launched; Codex's method check | The walker extended and proved, the manifest, a pilot, both Codex files saved |
