## 1. Non-finite path

**How a bite can be non-finite, and what the code does**
- **Untrimmed silent or near-silent source.** The unlimited pass gives a non-finite loudness, so the solver returns a gain of 0 and runs no limited pass (`src/audio/gain-solve.ts:96-104`). `chainLufs` stays null (`audio-plan.ts:367`), so the bite is null.
- **A limited pass that gives a non-finite loudness** (-Infinity or NaN) while the unlimited pass was finite. The solver stops at that pass (`gain-solve.ts:118`), but `chainLufs` has already been overwritten with the non-finite value (`audio-plan.ts:452`). The `isFinite` guard (`:468`) then gives null.
- **A trimmed keep with less than one block of sound.** `planAudio` returns `KeptSilence` and makes no plan (`audio-plan.ts:350-353`). The pipeline then passes null (`pipeline.ts:350-372`, `:874`).
- **+Infinity is never produced.** Both operands are guarded, and the gain is finite (`gain-solve.ts:106`, with each step bounded at `:78`).

**What follows from a null bite**
- The warning is absent (`warnings.ts:207`). A NaN would also give no warning, because `NaN > 3` is false.
- The log shows null (`audio-plan.ts:489`).
- The page can never show "NaN": the warning's text is fixed and carries no number (`src/ui/warning-text.ts:100-101`). The test pinning that wording is `src/ui/warning-text.test.ts:147` ("says the sheet's B11 words, whatever the bite").
- Nothing throws.

## 2. Lowered-ceiling path

**Where it lives and what happens**
- The ceiling starts at `LIMITER.ceilingDbtp`, -3 dBTP (`audio-plan.ts:374`; `src/config/audio.ts:230`).
- It is lowered at most once, from the codec probe's measured overshoot (`audio-plan.ts:441-442`; the rule is `limiterCeilingFor`, `src/media/codec-probe.ts:138-146`).
- That happens only when an encoder config is given. In the app it always is, for the preset's codec (`pipeline.ts:368`).
- When the ceiling moves, the probe pass is measured again at the same gain under the new ceiling (`audio-plan.ts:448`). `measureChain` reads the current ceiling each time it runs (`:410`), so every later pass uses the new one.
- `chainLufs` comes from that second measurement (`:452`).
- Pass C runs the same ceiling: `plan.limiterCeilingDbtp` (`:512`, `:571-572`).
- **So the bite is computed against the lowered ceiling, not the nominal one.** It therefore includes the extra limiting that the codec's headroom forces.

**Existing tests:** none pins this.
- `sub-block-sound.test.ts:124` passes no encoder config (`:130`), so it only ever sees the nominal ceiling.
- `src/media/codec-probe.test.ts:178-222` (`limiterCeilingFor`) tests the ceiling rule, not the bite.
- `chain.test.ts:328`, `:370` ("holds a lower ceiling when the job asks for one") test the chain, not the bite.
- The Chrome evidence (`reviews/2026-10-24/vh193-heavy-2026-10-25.md`, walker `heavy-193.mjs:137`) records the logged bite but not the logged ceiling (`audio-plan.ts:495`). So the path is not evidenced even through the log.

**Probe L1** (passed). The fake codec probe reports a 2.5 dB overshoot and no loudness cost, so only the ceiling differs from a nominal run. Result:
- The ceiling became -5 dBTP, which equals `limiterCeilingFor(2.5)`.
- The passes ran as expected: the null-gain pass; the probe pass at -3; the same gain again at -5; every later pass at -5; the last pass at the plan's gain.
- The plan's bite equals a fresh real chain measured at -5, and is clearly different from the same gain measured at -3:

| Signal | Plan's bite (ceiling -5) | Fresh chain at -5 | Same gain at -3 | Nominal plan's bite |
| --- | --- | --- | --- | --- |
| clicks | 19.8435 | 19.8435 | 19.2657 | 18.84 |
| moderate | 0.5397 | 0.5397 | 0.1604 | 0.06 |

**Verdict:** correct by design ("the chain that will actually run") and not a defect, but untested in the repo; proved here only by the probe.

**Missing evidence:** a repo test with a faked `CodecProbe` like L1. Node has no WebCodecs encoder, so the test needs `vi.mock`; no product change is needed.

**Informational:** a lowered ceiling alone raised the "moderate" bite from 0.06 to 0.54 LU, so a preset whose codec overshoots more can move a file towards the 3 LU warning.
