# VH-183 — the trim's Page step, measured in Chrome (2026-10-24)

What it checks: Page Up and Page Down move a trim handle by max(10 s, 1% of
the video), and the arrows, Home, End and what each handle says are as
before. Instrument:
`design-pass-2/evidence/measurements/walker/page-183.mjs`, headless Chrome
over CDP against the Vite dev server, real key events, no click or set value
once a handle has focus.

Fixtures: `lecture-130s.mp4` (130 s, so a 10 s page) and `still-3600s.mp4`
(an hour, so a 36 s page), from the walker's `fixtures.sh`.

Grid: 2 files × 3 languages (en-GB, zh-Hans, ms-MY) × 3 widths (1280, 375,
320 px) × 4 colour modes (light, dark, forced-light, forced-dark) = 72 cases.

The readings, every case and key: `vh183-page-step-2026-10-24.json`, each
step as `[handle, key, value in s, aria-valuetext, focused]`.

## Result: 72 of 72 as expected, focus held on the handle throughout

Each case presses, on the start handle: Page Up, Page Up, Page Down, →, End,
Page Up, Home, Page Down; then on the end handle: Page Down, Page Up, Home,
Page Down, End.

| Fixture | Start handle values (s) | End handle values (s) |
| --- | --- | --- |
| 130 s | 0 → 10 → 20 → 10 → 11 → 127 → 127 → 0 → 0 | 130 → 120 → 130 → 3 → 3 → 130 |
| 3,600 s | 0 → 36 → 72 → 36 → 37 → 3,597 → 3,597 → 0 → 0 | 3,600 → 3,564 → 3,600 → 3 → 3 → 3,600 |

Every case matched its row exactly. The arrow kept its 1 s; End and Home
went to the handle's bounds (the end handle stops 3 s after the start,
`KEPT_MIN_SECONDS`); a page at either bound stayed there.

## What a screen reader hears: unchanged

`trimHandleText` is untouched. Each language gave one `aria-valuetext`
sequence across all 12 width and mode cases, worded as before:

- en-GB, the hour: "the beginning", "36 seconds", "1 minute 12 seconds", …, "59 minutes 57 seconds", "the end", "59 minutes 24 seconds".
- zh-Hans: 开始, 36秒钟, 1分钟12秒钟, …, 结束.
- ms-MY: permulaan, 36 saat, 1 minit 12 saat, …, penghujungnya.

## Not measured

No visual change was made, so no capture is kept. A person on a real
screen reader was not asked; the readings are the attribute, not speech.
The before was not run: on the base the page was a fixed 10 s, which the
130 s rows still show.
